Following the foundation of the v3.0.0 engine, `v3.1.0-beta.1` is the project's most ambitious release yet. Developed on-and-off over the past 3 months (navigating life's interruptions, but we got there!), this release shifts `hifi-wifi` from user-space system configurations to a true kernel-integrated network performance utility.

Here are the three massive architectural pillars of this update:

1. **Kernel-Space Execution (Zero-Copy BPF Game Bypass)**
   Instead of relying on standard network queues, we now inject custom eBPF programs directly into the network driver interface. The engine intercepts UDP packets (Moonlight, Sunshine, Steam Link) on arrival and maps them to high-priority classes, bypassing host socket overhead for near-zero latency.
2. **Telemetry-Driven Adaptive Redundancy (Temporal Packet Duplication)**
   To protect cloud streams from packet loss and jitter, the engine continuously monitors TCP socket stats via socket telemetry (`getsockopt`). If jitter or packet loss spikes, it dynamically duplicates outgoing game traffic at the kernel level using Netfilter, automatically suppressing it when congestion is detected or conditions stabilize.
3. **Fail-Safe Portability & Resiliency (Built for Handheld OSes)**
   Engineered to run flawlessly on read-only handheld operating systems (like SteamOS and Bazzite). Features include a pre-flight system compatibility scanner (`check-compat`), a block-on-incompatible installer, and a detached panic recovery hook that automatically reverts all network stack changes to factory defaults if the daemon unexpectedly crashes.

## Technical Details

### 1. Zero-Copy eBPF/XDP Game Bypass
Rather than letting game traffic wait in standard operating system socket queues, the engine utilizes kernel-level BPF (Berkeley Packet Filter) code to process packets at the driver level.
- **Dynamic BPF Compilation:** On startup, the engine checks for the availability of the `clang` compiler and dynamically compiles `game_bypass.c` into a BPF object (`game_bypass.o`).
- **Ingress Qdisc Attachment:** Automatically attaches the BPF classifier to the `ingress` qdisc of your active network interface, inspecting and tagging packets on arrival.
- **Expedited Priority Mapping:** The BPF program inspects UDP headers for known streaming and gaming ports (Moonlight: `47998-48010`, Steam Link: `27031-27036`) and sets `skb->priority = 6` (Expedited Forwarding class) to bypass standard latency queues.
- **Legacy TC Fallback:** If `clang` is missing or BPF loading is blocked by kernel security policies, the engine falls back to legacy `tc filter u32` classifiers with `skbedit` priority actions, achieving identical priority classification.

### 2. Temporal Packet Duplication (Single-Link Redundancy)
Protects real-time streams from packet drops and wireless interference by establishing packet-level redundancy on the active interface.
- **Active Retransmit & Jitter Telemetry:** Monitors TCP socket stats for active gaming processes (`getsockopt` via `TCP_INFO`). If segment retransmissions increase or RTT jitter exceeds the configured threshold (default `15ms`), duplication is triggered.
- **Kernel-Level Packet Duplication:** Automatically sets up `iptables` rules using the `TEE` target, duplicating outgoing Moonlight and Steam Link UDP streams to the default gateway of the active network interface.
- **Loop Prevention:** Configures `MARK` targets to tag duplicated packets (with mark `0x99`), preventing infinite packet-cloning loops.
- **Dynamic Deactivation & Hysteresis:** Once network conditions on the primary interface stabilize, the duplication rules are torn down to preserve battery life and bandwidth.
- **Dynamic Congestion Auto-Suppression:** Prevents local link saturation by continuously monitoring primary interface bandwidth using TC class counters (`1:11` and `1:12`) and calculating available headroom based on link rates. If the available link headroom falls below `10 Mbps` (e.g. on 2.4 GHz bands or weak 5 GHz cells), packet duplication is automatically deactivated or prevented to avoid exacerbating congestion.

### 3. Unified Governor Integration & Configuration
The entire lifecycle of the new datapath features is managed by the central governor loop.
- **Seamless Game Mode Hooks:** The eBPF bypass and temporal packet duplication systems are automatically initialized when Game Mode is triggered (detected via interface PPS thresholds).
- **Graceful Shutdown:** Unloading the daemon or stopping the `hifi-wifi` service triggers a complete cleanup of all active BPF filters, ingress qdiscs, and `iptables` mangling tables.
- **Dynamic ethtool Coalescing Detection:** The system optimizer now dynamically queries the interface driver for interrupt coalescing capabilities before applying latency tunings, ensuring compatibility across diverse network adapters (such as wireless and ethernet) without risks of system instability.
- **Media-Aware Congestion Switching:** The governor dynamically monitors active network media and switches the host-level TCP congestion control algorithm on the fly. BBR remains the global default system baseline to guarantee flat, low-latency performance on unshaped high-speed networks. The system only pivots to Cubic when a hard-clamped CAKE shaper is actively running and saturated below the physical wire speed, maximizing queue efficiency.
- **New Config Options:** Added `ebpf_bypass_enabled`, `multipath_bonding_enabled`, `multipath_packet_loss_threshold`, and `multipath_jitter_threshold_ms` to `hifi-wifi.toml`. Added the `[multipath]` section with options for `game_stream_bitrate` and `auto_suppress_on_congestion`.
- **Configurable TCP Congestion Control:** Added `tcp_congestion_control` configuration option (defaulting to BBR), allowing users to switch the global congestion control algorithm (e.g., Cubic vs BBR) in the `[system]` section.

### 4. Safety Containment & Compatibility Safeguards
Designed with robust sandboxing and recovery systems to ensure that testing kernel-space features does not leave the host's networking stack in a broken state.
- **Pre-Flight Subcommand (`check-compat`):** Adds a CLI flag (`hifi-wifi check-compat`) that scans the running system for required and optional networking dependencies (eBPF capabilities, `xt_TEE` Netfilter module, TCP BBR/Cubic availability, and configuration tools) and renders a clean markdown status table.
- **Block-on-Incompatible Install:** The installation flow (`install.sh` and the internal `install` command) runs the compatibility scanner, automatically aborting the installation process and logging the exact missing requirements if mandatory tools (such as Traffic Control `tc` from `iproute2`) are missing.
- **Panic Hook Recovery Routine:** Configures a process-level panic hook (`std::panic::set_hook`). If the daemon suffers an unexpected crash, the hook intercepts termination and executes a detached `revert` process to automatically clean up all modified routing rules, eBPF filters, power-save overrides, and iptables tables, leaving the system stack completely clean.
- **Sysctl Isolation Sandbox:** Dynamic TCP congestion switching is fully isolated; failures to modify kernel values (common on locked-down or custom kernels) are handled as safe system log warnings, preventing Tokio task panics.
